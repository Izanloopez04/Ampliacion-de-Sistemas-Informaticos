[00:01] - Preparando el terreno

FASE 1: DOMANDO EL HARDWARE

Como estamos en un Mac, nos olvidamos de las librerías estándar de NVIDIA. Aquí mandan MLX y Metal. Primero creamos un entorno limpio para no romper nada y compilamos el motor desde cero.

# Un rincón seguro para mis cosas... $ python3 -m venv venv && source venv/bin/activate

# Instalando el motor de Apple... $ pip install mlx-lm

# Construyendo el núcleo de llama.cpp (a toda máquina con Metal) $ cmake -B build && cmake --build build --config Release -j
[00:05] - Alimentando a la bestia

FASE 2: LA RECETA DEL ÉXITO (DATASET)

No podemos soltar al bot sin darle un libro de cocina. He estructurado los datos en formato JSONL, usando las etiquetas de 'Phi-3' para que el modelo sepa cuándo hablo yo y cuándo le toca responder a él.

# Ejemplo de lo que hay en el menú de entrenamiento: {"text": "<|user|>Oye, tengo patatas...<|end|><|assistant|>¡Fácil! Una buena tortilla...<|end|>"}
[00:10] - Gimnasio neuronal

FASE 3: ENTRENAMIENTO LORA

En lugar de reentrenar todo el modelo (que nos llevaría siglos), usamos LoRA. Es como ponerle un "parche de conocimiento" específico de cocina sobre su cerebro de propósito general.

# A sudar un poco... $ python -m mlx_lm.lora --config config_chef.yaml --train

Resultado: Los adaptadores ya están listos en la carpeta ./adapters. Ya sabe freír un huevo.

[00:25] - El toque final

FASE 4: FUSIÓN Y COMPRESIÓN

Ahora toca unirlo todo. Cogemos el modelo base, le pegamos lo aprendido y lo comprimimos a q4_k_m. ¿Por qué? Para que vuele sin gastar toda la RAM del Mac.

# Mezclando el modelo base con mis adaptadores... $ python -m mlx_lm.fuse --model microsoft/Phi-3-mini-4k-instruct --adapter-path adapters --save-path merged_model

# Convirtiendo a formato GGUF y apretando los tornillos (cuantización) $ ./llama.cpp/build/bin/llama-quantize chef-bot-f16.gguf chef-bot-q4.gguf q4_k_m
DIARIO DE ERRORES (O "POR QUÉ NO FUNCIONÓ A LA PRIMERA")

• El lío de versiones: Torch se puso caprichoso con la versión Nightly.

Volví a la versión estable y usé MLX-LM para gestionar la memoria.

• El Makefile fantasma: Intenté usar el Makefile antiguo y falló.

Cambié a CMake; mucho más moderno y menos problemas de rutas.

• Rutas perdidas: El script no encontraba los adaptadores.

Un simple "mv" para ponerlos en la raíz y todo arreglado.
