Open Code Node.js LLM Local

1. Arquitectura del Ecosistema

Hemos diseñado una solución de asistencia en programación orientada a la privacidad total. El sistema opera al 100% en local, aprovechando la aceleración de hardware del Mac para eliminar la dependencia de servicios en la nube. El esquema se divide en dos pilares fundamentales:

  • Núcleo de Inteligencia (Servidor): LM Studio gestionando un modelo Llama-3 mediante una infraestructura de API local.
  • Interfaz de Acción (Cliente): El agente OpenCode, encargado de la orquestación y ejecución de scripts directamente en el entorno del sistema operativo.

2. Protocolo de Instalación

Fase 1: Levantamiento del Servidor Inferencial

Configuramos LM Studio para que actúe como un puente de comunicación estandarizado (compatible con OpenAI) para el consumo del modelo.

  • Engine: Meta Llama 3 8B Instruct.
  • Socket: Puerto 1234.
  • Seguridad: Políticas de CORS habilitadas para permitir la interacción del agente.
Terminal de control: Servidor activo, puerto 1234 vinculado y GPU Apple Metal en uso.

Fase 2: Orquestación del Agente

Dada la naturaleza específica del paquete, realizamos un enlace manual del motor del agente mediante la configuración del perfil de usuario.

Inyectamos la configuración en ~/opencode/opencode.json para redirigir el flujo de pensamiento al localhost:

{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "lmstudio": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "LM Studio Local",
      "options": {
        "baseURL": "http://127.0.0.1:1234/v1"
      },
      "models": {
        "modelo-local": {
          "name": "local-model"
        }
      }
    }
  }
}

3. Registro de Incidencias y Depuración

Durante el proceso de despliegue, surgieron retos técnicos que requirieron ajustes finos en la lógica de conexión y permisos:

Incidencia A: Disponibilidad de Dependencias

Diagnóstico: Error E404 en el registro público de NPM.
Resolución: Se omitió la instalación global y se procedió a la configuración directa del JSON en el directorio raíz del usuario para enlazar los binarios locales.

Incidencia B: Sesgo del System Prompt

Diagnóstico: El modelo negaba su propia integración local ("Alucinación de Identidad").

Se determinó que las instrucciones de sistema originales causaban un conflicto de personalidad. Se ajustaron las directivas para que el modelo reconociera su entorno técnico real.

Incidencia C: Restricciones de SIP en macOS

Diagnóstico: Denegación de escritura en rutas protegidas por el sistema operativo.
Resolución: Reorientación del espacio de trabajo. Se definieron nuevas rutas de salida en el entorno del usuario: /Users/aulaateca26/Desktop.

4. Validación y Resultados

El sistema se encuentra totalmente operativo. El agente no solo genera código Python optimizado, sino que tiene autonomía para crear, escribir y ejecutar scripts en el entorno local de forma segura.

Validación final: Ciclo de ejecución completado con éxito y salida de terminal confirmada.
